## 一、口径（一句话）

**只投递「邮箱档位 = A 档」的信。B 档、B− 档、C 档一律暂缓，不投递。**

> ⚠️ 注意：这里的「档」是**邮箱档位**（能不能可靠送达），
> **不是**客户类型档（A 类承包商 / B 类分销商）。
> 一家 B 类分销商，只要邮箱是 A 档，**照发**。

---

## 二、档位定义（沿用 batch5 交接单口径）

| 档 | 定义 | 本轮处置 |
|---|---|---|
| **A** | **具名 + 已验证 / 第一方来源**（官网、协会名录、SMTP 实证命中） | ✅ **投递** |
| **B** | 角色邮箱（`info@` / `sales@` / `contact@`）或域不可探测 | ⏸ **暂缓** |
| **B−** | catch-all 域的具名邮箱（无法验证，只能靠退信判断） | ⏸ **暂缓** |
| **C+** | 弱（品牌域已死、个人邮箱等） | ⏸ **暂缓** |
| **—** | 无可用邮箱 | ⛔ 不可发（改电话） |

## 五、🔴 为什么只发 A 档（三条依据）

### 5.1 B 档的退信率显著更高（有数据）

`退信处理清单.md` §五 的统计：16 个退信地址里 **7 个是角色邮箱**（`info@` / `contact@` /
`feedback@` / `supplier@`）。角色邮箱是**共享箱**，反垃圾策略更严、更易被网关直接拒。

### 5.2 B 档「点名转交」依赖对方配合，转化不确定

角色邮箱必须写「请转交给 XXX」——**信到不到得了决策人手里，不由我们控制**。
A 档是直呼其名进本人邮箱，**送达即触达**。

### 5.3 保护发信域信誉（最重要）

本项目发信域 `jiezougroup.com` 的信誉是**不可再生资源**。
B 档退信率更高 → 拖累域信誉 → **连带影响 A 档的送达率**。
**用 A 档养信誉，比用 B 档冲量划算得多。**

## 六、B 档什么时候可以解禁（前置条件）

**不建议永久放弃 B 档**，但要先把下面几件事做完：

| # | 前置条件 | 现状 |
|---|---|---|
| 1 | **B 档地址先做验证**（MX + SMTP 探活），不直接发 | ⬜ 待办 |
| 2 | **catch-all 域**（Trueline / RIES / {{COMPANY}} / Jebco / Beaver / Access / UTB / IES）需另找验证手段 | ⬜ 待办 |
| 3 | **源 IP 信誉问题解决**（Spamhaus / Mimecast / Charter 封锁） | 🔴 **未解决** —— 这是最硬的阻塞项 |
| 4 | **A 档发送稳定**（连续几批无异常退信） | ⬜ 观察中 |

> 🔴 **第 3 项是全局阻塞**：源 IP `223.64.2.43` 被多方标记，
> **不解决则大量邮箱（尤其 M365/EO 域）根本无法投递** —— 与档位无关。
> 详见 `开发信项目/交接单/batch5_new_129plus/_批次汇总.md` §八。

## 七、给后续环节的约束

1. **建队列时只收 A 档** —— 建队列脚本应按交接单的「邮箱档位」字段过滤
2. **B 档不进队列**，避免误发
3. **每次投递前查退信黑名单**（含**整域封锁**，2026-09-29 新增）
4. **收到回信不受档位限制** —— B 档若回了信，照常登记与回复（回信是对方主动，性质不同）
