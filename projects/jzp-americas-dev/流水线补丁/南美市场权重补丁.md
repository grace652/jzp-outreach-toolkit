# 南美市场权重补丁

**目的**：让现有线索流水线能正确识别并分级南美买家。

**背景**：2026-09-27 实测发现，把一份 76 家南美机构名单导入流水线后，结果是 `A 0 / B 0 / C 2 / D 74`，其中巴西、智利、哥伦比亚、秘鲁、阿根廷的机构**全部被打 0–15 分并贴上「非目标市场」标签**，包括拉美最大电力公司 Eletrobras（AXIA Energia，得 0 分、判为 D 级「暂不跟进」）。这会让南美线索在数据层面被系统性筛掉。

---

## 一、根因（两处，缺一不可）

### 根因 1 · 国别解析表缺南美国家

`scripts/customs_normalize.py:149` 的 `COUNTRY2`（英文国名 → 2 位码）里**只有 `ECUADOR` 和 `MEXICO` 两个拉美国家**，没有 BRAZIL / CHILE / PERU / COLOMBIA / ARGENTINA。

后果：如果来源文件的国家字段是英文（如 ImportYeti 导出、Trado 导出、英文名录），`country2_of()` 返回 `""`，然后走 `lead_scoring.py:236` 的兜底分支：

```python
add(3, WEIGHTS[3][0], "国别未识别，按非目标市场处理")   # −15 分
tags.add("国别未知")
```

如果来源是中文（如广交会名录），`CJK_COUNTRY` 里**有**「巴西」「智利」「秘鲁」等，能正确解析出 `BR`/`CL`/`PE`，但紧接着走 `lead_scoring.py:233` 的分支：

```python
add(3, WEIGHTS[3][0], f"非目标市场（{c2}）")            # 同样 −15 分
tags.add("非目标市场")
```

**两条路径都落到 −15 分**，只是标签不同。

### 根因 2 · 市场分层集合未覆盖南美

`scripts/customs_normalize.py:279`：

```python
SECONDARY_MARKETS = {"MX", "PR", "DO", "TT", "JM", "BS", "BB", "BZ", "GT", "HN", "PA", "CR"}
```

这是加勒比与中美洲的组合，南美国家一个都没有。

## 二、补丁 A（推荐先做 · 已实测）

**改动文件**：`scripts/customs_normalize.py`（1 个文件，2 处）
**自测影响**：无。`selftest_pipeline.py` 26/26 全绿，**不需要重生成基线**。

### 改动 1 · `COUNTRY2` 增加南美英文国名

在第 155–157 行（`"UZBEKISTAN": "UZ", ... "UNITED ARAB EMIRATES": "AE",` 之后）追加：

```python
    # 南美（2026-09 新增）。只加全名，不加 2 位码——见下方说明。
    "BRAZIL": "BR", "CHILE": "CL", "PERU": "PE", "COLOMBIA": "CO",
    "ARGENTINA": "AR", "BOLIVIA": "BO", "PARAGUAY": "PY", "URUGUAY": "UY",
    "VENEZUELA": "VE", "GUYANA": "GY", "SURINAME": "SR",
```

### 改动 2 · `SECONDARY_MARKETS` 纳入南美

把第 279 行整行替换为：

```python
SECONDARY_MARKETS = {
    "MX", "PR", "DO", "TT", "JM", "BS", "BB", "BZ", "GT", "HN", "PA", "CR",
    # 南美（2026-09 新增）。此前 BR/CL/PE/CO/AR/EC 等既不在 TARGET 也不在
    # SECONDARY，会被判为「非目标市场」扣 15 分并打标签，与南美开发战略冲突。
    # 60Hz 美标体系（与 UL/cUL/CSA + IEEE C57.12 产品线直接适配）：
    "BR", "PE", "CO", "EC",
    # 50Hz 欧标体系（同容量铁芯截面需加大，属重设计成本）：
    "CL", "AR", "BO", "PY", "UY", "VE",
}
```

### ⚠️ 关键工程判断：不要给 `COUNTRY_ALIASES` 加 2 位码

`COUNTRY_ALIASES`（第 161 行）是给缩写用的，看起来加 `"BR": "BR"` 很自然。**但不要这么做。**

原因：`country2_of()` 的匹配对象是 `buyer_country + buyer_address + buyer_region` 三段**自由文本**拼起来的字符串，用的是宽松的正则：

```python
if re.search(rf"(?<![A-Z]){re.escape(name)}(?![A-Z])", blob):
```

这意味着地址里的 `"ABC ELECTRIC CO., LTD"` 会命中 `CO` → 被判定为**哥伦比亚**。同理 `PE`（可能是公司名片段）、`AR`、`BR`、`CL`、`BO` 都有误伤风险。

现有表里 `CA` 已经承担了这个风险（会被 `CA` 州码/公司名误伤），但那是历史遗留，**不要因为「已经有先例」就扩大这个风险面**。南美国家用全名匹配（`BRAZIL` 不会误伤任何东西）已经足够。

> 如果确实有来源只给 2 位码，正确做法是在 `local_csv` 适配器里用 `--map` 把该列映射为 `buyer_country2`（`lead_scoring.py:120` 会优先读取这个字段，跳过文本推断），而不是往 `COUNTRY_ALIASES` 里塞。

## 三、补丁 B（推荐做 · 已实测）

**改动文件**：`customs_normalize.py` + `lead_scoring.py`（各 1 处）
**自测影响**：无。**只加标签，不动权重**，`expected_scores.csv` 基线不受影响，26/26 仍全绿。

### 改动 3 · 新增两个分层集合

在补丁 A 的 `SECONDARY_MARKETS` 之后追加：

```python
# 南美分层标签用（不参与打分，仅用于线索表打标与筛选）。
# 60Hz 与 UL/cUL/CSA + IEEE C57.12 产品线直接适配，为第一梯队；
# 50Hz 需重算铁芯截面与损耗，为第二轮。详见作战手册第 1.3 节。
LATAM_60HZ_MARKETS = {"MX", "BR", "PE", "CO", "EC"}
LATAM_50HZ_MARKETS = {"CL", "AR", "BO", "PY", "UY", "VE"}
```

### 改动 4 · `lead_scoring.py` 打分分支加标签

`scripts/lead_scoring.py:231-232`：

```python
    elif c2 in cn.SECONDARY_MARKETS:
        add(2, WEIGHTS[2][0], f"次级美洲市场（{c2}）")
        # 南美分层标签（不影响分数，只用于线索表筛选与话术分组）
        if c2 in cn.LATAM_60HZ_MARKETS:
            tags.add("南美60Hz优先")
        elif c2 in cn.LATAM_50HZ_MARKETS:
            tags.add("南美50Hz第二轮")
```

**为什么用标签而不是调权重**：调权重（把 60Hz 市场从 +8 提到 +18）会改变 `data/fixtures/expected_scores.csv` 的基线，需要按 README 的说明重新生成基线，属于「会动到审计链」的改动。而标签分层**零风险**，且已经足够支撑实际操作——你可以直接按标签筛选线索表、分组发不同语言的邮件。**建议先用标签跑一个季度，确有需要再考虑调权重。**

## 四、实测效果对比

对同一份 76 家南美机构名单（`线索资产/南美首批目标客户.csv`）：

| 指标 | 打补丁前 | 补丁 A | 补丁 A + B |
|---|---|---|---|
| 分级结果 | A 0 / B 0 / **C 2 / D 74** | A 0 / B 0 / **C 5 / D 71** | 同左 |
| Eletrobras（AXIA Energia，BR） | **0 分**，标签「非目标市场」 | 23 分 | 23 分 + 标签「南美60Hz优先」 |
| CPFL Energia（BR，唯一有公开邮箱的） | 15 分，标签「非目标市场」 | **38 分** | 38 分 + 标签「南美60Hz优先」 |
| 巴西 / 秘鲁 / 哥伦比亚 / 智利 / 阿根廷机构 | 0–15 分，全部贴「非目标市场」 | 23 分，无负面标签 | 23 分 + 60Hz/50Hz 分层标签 |
| 自测 `selftest_pipeline.py` | 26/26 | **26/26（基线未变）** | **26/26（基线未变）** |

分层标签分布：**南美60Hz优先 59 家**（墨西哥 15 / 巴西 15 / 哥伦比亚 16 / 秘鲁 11 / 厄瓜多尔 2）、**南美50Hz第二轮 17 家**（智利 14 / 阿根廷 3）。

## 五、必须理解的一点：分数低 ≠ 线索质量差

打补丁后这批名单**仍然全是 C/D 级**，最高 38 分。这不是补丁没生效，而是**来源数据完整度只有 21%**。

`leads.csv` 的 `coverage` 列会明确标出这一点。这份名单是一份**定向目标清单**（机构名 + 官网 + 采购入口），不含票数、金额、日期、供应商——而这些正是打分模型里权重最高的信号（「竞对买家」+30、「采购频次高」+15、「近期活跃」+12）。

你的 README 里已经写了这条警告：

> **低完整度的 35 分不能和提单口径的 170 分直接比较。**

所以正确的用法是：

1. **用这份名单做「定向外呼」**——它的价值在于「这家机构是谁、怎么联系、采购入口在哪」，不在于打分排序。
2. **想要打分有意义，必须补一份提单级数据**。对美国用 ImportYeti（免费版即可）；对南美用 Trademo 或 Volza 的试用版，验证数据新鲜度后再付费。
3. **两条线并行**：定向名单走人工触达，提单数据走流水线打分。不要指望一份目录名单能在打分模型里跑出 A 级。

## 七、未包含在补丁里的两项（有意为之）

1. **没有把墨西哥从「次级市场 +8」提升到更高权重**。调研结论认为墨西哥是南美第一优先市场，但把它单独提到 +18 需要动权重与基线。当前用标签 `南美60Hz优先` 已能把它与加勒比市场区分开。
2. **没有改 `REGION_NAMES` / `REGION_LABEL`**。这两个表只覆盖美国州名与加拿大省名，所以南美机构的 `region` 字段会显示为原始文本（如 `São Paulo`）而不是可读标签。这不影响打分（`region_of` 找不到就返回 `""`），只影响展示。

   > ⚠️ 如果以后要补南美行政区划，**注意巴西州码与州名会和美国的撞车**：PA（Pará / Pennsylvania）、MA（Maranhão / Massachusetts）、MT（Mato Grosso / Montana）、MS（Mato Grosso do Sul / Mississippi）、AL（Alagoas / Alabama）、SC（Santa Catarina / South Carolina）、PR（Paraná / Puerto Rico）。`region_of()` 对 2 字母 token 是无条件匹配的，直接加进去会造成误判。**建议南美地区只存全称，不存州码。**
