# DKIM 与 DMARC 配置操作指南（腾讯企业微信 / 企业邮）

> 生成：2026-10-03 18:50
> 适用：`jiezougroup.com`（腾讯企业邮，DNS 托管在 **DNSPod**）
> 依据：腾讯企业微信官方帮助中心（`open.work.weixin.qq.com/help2/pc/19647`、`/21540`）+ 2026-10-03 实测

---

## 〇、先分清：这两个东西的获取方式完全不同

| | **DKIM** | **DMARC** |
|---|---|---|
| 作用 | 邮件数字签名，防**篡改** | 认证策略 + 报告，防**冒用** |
| **从哪来** | **腾讯后台生成**，你复制公钥 | **你自己写**，按标准格式填 |
| 有没有「生成」按钮 | ✅ 有 | ❌ **没有** |
| 主机记录 | 后台给你（如 `dkim._domainkey`） | 固定 `_dmarc` |
| 记录值 | 后台给的一长串 | 你自己拼 |

> **一句话**：DKIM 你**不能自己造**（私钥在邮局手里，你只能拿公钥）；
> DMARC 你**必须自己写**（没有任何生成入口）。

## 二、DKIM 怎么获取（5 步）

### 第 1 步 · 确认域名状态
企业微信管理后台 → **【协作 → 邮件 → 邮箱域名】**
→ 确认 `jiezougroup.com` 状态是「**使用中**」

> 如果显示「未验证」或其他，先解决域名绑定，否则 DKIM 页面可能进不去。

### 第 2 步 · 进 DKIM 页面
企业微信管理后台 → **【协作 → 邮件 → 安全管理 → DKIM验证 → 配置】**

⚠️ 注意路径：是 **「安全管理」** 下面，不是「域名管理」下面。
（旧版企业邮后台是 `exmail.qq.com` → 域名管理 → DKIM，两处都找一下）

### 第 3 步 · 复制三条信息
页面会显示三条，**原样复制，一个字都别改**：
- **主机记录**（形如 `dkim._domainkey`）
- **记录类型**（TXT）
- **记录值**（一长串，含 `v=DKIM1; k=rsa; p=...`）

### 第 4 步 · 加到 DNSPod
腾讯云控制台 → 搜「DNS 解析 DNSPod」→ 找到 `jiezougroup.com` → 点「解析」→ **添加记录** → 类型选 **TXT** → 把上面三条对应填入 → 保存

### 第 5 步 · 回后台点验证（**这步最容易漏**）
回到【DKIM验证】页 → 点「**已完成配置，立即验证**」→ 状态变成「**已验证**」才算成功

> DNS 生效通常几分钟，慢的话 1 小时。**不点验证，状态会一直停在「验证中」。**

## 三、DMARC 怎么获取（自己写，没有生成入口）

在 DNSPod 加一条 TXT：

| 字段 | 填什么 |
|---|---|
| 主机记录 | `_dmarc` |
| 记录类型 | TXT |
| 记录值 | `v=DMARC1; p=none; rua=mailto:{{SENDER_EMAIL}}; fo=1` |
| TTL | 600 |

### 🔴 为什么我建议先用 `p=none`，而不是官方文档写的 `p=reject`

腾讯官方文档给的示例是 `v=DMARC1;p=reject;rua=mailto:...`。

**但对你这套系统，直接上 `p=reject` 有实际风险：**

`p=reject` 的含义是「凡是没有通过 SPF/DKIM **对齐**的邮件，一律拒收」。
你现在 **DKIM 还是空的**，如果还有别的地方在用 `jiezougroup.com` 发信
（阿里国际站、CRM、表单系统、第三方代发、邮件转发），**这些邮件会立刻被收件方拒掉** ——
包括正常业务邮件。

**正确顺序**：

```
p=none         ← 先这个：只监控、不拦截，观察 2–4 周
   ↓ 报告干净
p=quarantine   ← 软着陆：可疑邮件进垃圾箱
   ↓ 再观察 2 周
p=reject       ← 最终形态
```

**关于 `rua=`**：报告接收地址，**必须真实存在**，否则收不到报告。
可以直接填 `{{SENDER_EMAIL}}`（你自己的邮箱）。

## 四、怎么验证配好了

DNS 生效后（10 分钟–1 小时），跑这两条：

```bash
dig +short TXT dkim._domainkey.jiezougroup.com @8.8.8.8
dig +short TXT _dmarc.jiezougroup.com @8.8.8.8
```

**两条都有返回 = 配置成功。**

在线核查：<https://dnschecker.org>（选 TXT 类型，输入 `主机记录.域名`）

## 五、五个常见坑（官方文档明确列出的）

| 坑 | 说明 |
|---|---|
| **记录值带空格** | DKIM 记录值粘贴时常带换行/空格，**必须全部去掉**（官方列为首要失败原因）|
| **大小写被改动** | 按系统显示原样填，不要「规范化」大小写 |
| **主机记录写了全域名** | 只填 `dkim._domainkey` 即可，**不要**写成 `dkim._domainkey.jiezougroup.com`（DNSPod 会自动补域名）|
| **DMARC 一上来就 reject** | 见 §三，会误伤正常邮件 |
| **加完不点「立即验证」** | DKIM 必须回后台点一下，否则状态永远是「验证中」 |

## 六、时间表与影响

| 时间 | 动作 | 风险 |
|---|---|---|
| **今天** | 配 DKIM + DMARC(`p=none`) | 无风险，纯监控 |
| 2–4 周后 | 看 DMARC 报告，确认无合法邮件被误判 | — |
| 再 2 周 | 升 `p=quarantine` | 轻微 |
| 再 2 周 | 升 `p=reject` | 需确认报告干净 |

**对当前两个目标的作用**：
- **直接降低「服务商拒收」类软退信** —— 当前 3 家退信里有 2 家是这一类
- **提升整体送达率** → 顺带帮到回复率目标（邮件进垃圾箱的比例下降）
