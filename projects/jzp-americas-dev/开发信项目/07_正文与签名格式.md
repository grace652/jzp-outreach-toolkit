# 07 · 正文与签名格式（2026-09-27 用户规定）

> 🔴 **本文件是正文边界的唯一权威定义。** 与 `00` §5.4 的「3 块正文」配合使用。

---

## 一、正文与签名的分界

**正文止于 `{{SENDER_NAME}}`。** 之后的两行**不属于正文**，由发信层自动追加。

```
【正文】
Hi Aaron,
...
Best regards,

{{SENDER_NAME}}          ← 正文最后一行
─────────────────────────────────────────
【签名】（不写进正文文件，发信时自动追加）
Sales Manager | JZPE POWER TRANSFORMER CO., LTD.
{{SENDER_EMAIL}} | WhatsApp {{SENDER_PHONE}}
```

**拼接后的完整效果：**

```
Best regards,

{{SENDER_NAME}}
Sales Manager | JZPE POWER TRANSFORMER CO., LTD.
{{SENDER_EMAIL}} | WhatsApp {{SENDER_PHONE}}
```

---

## 二、规则

| 项 | 规则 |
|---|---|
| 正文文件内容 | 从称呼（`Hi X,` / `Dear X,`）到 `{{SENDER_NAME}}` 为止 |
| 签名 | **不写进正文文件**，存于 `签名_纯文本.txt` |
| 发信 | 发件箱自动追加签名，正文 + 空行 + 签名 |
| 中文字段 | 中文批注里不再重复署名主体行 |

**为什么这样分**：正文是"每封都不同"的部分，签名是"每封都一样"的部分。
分开后，改签名只需改一个文件，不用动 100+ 封信。

## 三、⚠️ 合规提醒（必须知道）

### 当前签名缺**实体邮寄地址**

| 法域 | 要求 | 现状 |
|---|---|---|
| **美国 CAN-SPAM** | 商业邮件**必须**含有效的**实体邮政地址** | ❌ 缺 |
| **加拿大 CASL** | 商业电子讯息**必须**含发送者名称、**邮寄地址**、退订机制 | ❌ 缺 |

**两份法规都强制要求实体地址。** 当前签名只有职务/公司/邮箱/WhatsApp，**没有地址**。

### 项目原签名是有地址的

`02_product_positioning.md` §一 定义的署名主体包含：

```
{{SENDER_NAME}}
Sales Manager | JZPE POWER TRANSFORMER CO., LTD.
E  {{SENDER_EMAIL}}
M  WhatsApp / WeChat: {{SENDER_PHONE}}
W  www.jiezougroup.com
A  Building D, Suzhou Bay Center Plaza,
   Intersection of Zeshan Road & Junyi Road,
   Wuzhong District, Suzhou City, Jiangsu Province, China
```

**待用户确认**：是保留精简版（无地址），还是加回地址行？

**加回地址的最小改动**（保持你要的两行结构，只多一行）：

```
Sales Manager | JZPE POWER TRANSFORMER CO., LTD.
{{SENDER_EMAIL}} | WhatsApp {{SENDER_PHONE}}
Building D, Suzhou Bay Center Plaza, Wuzhong District, Suzhou, China
```

> 地址用**英文精简版**（`02` §一 已确认口径）。

## 四、两套签名系统并存（注意别混用）

| 系统 | 文件 | 用于 |
|---|---|---|
| **纯文本签名**（本文件定义） | `签名_纯文本.txt` | **开发信项目**（`clients/` 里的信） |
| HTML + CID 内嵌 | `签名导出/① 签名_内嵌版…html` | 另一套流水线（`发信草稿/`，**已废弃**） |

发件箱按正文类型自动选：
- 正文是**纯文本** → 追加 `签名_纯文本.txt`
- 正文是 **HTML** → 追加 `签名_内嵌版.html`（含 cid 图片）
