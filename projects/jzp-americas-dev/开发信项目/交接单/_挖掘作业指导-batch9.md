## 三、每家必做的四步（顺序不能反）

### 第 0 步 · ⓪ 层反身排除（🔴 最先做，一票否决）

**进官网读「业务描述原句」**，确认**不是**：
- 变压器/开关柜**制造商**（`we manufacture` / `our factory` / 自称 OEM）
- **竞品代理**（尤其 **YAWEI 亚威**）
- **「中国货源 → 北美」通道**

**🚨 危险信号 vs ✅ 安全信号**
| 🚨 危险 | ✅ 安全 |
|---|---|
| `manufacturer` / `we manufacture` / `our factory` | `distributor` / `supplier` / `stock` / `inventory` |
| `exclusive distributor of <对手品牌>` | `authorized distributor of <无竞争关系品牌>` |
| 产品线与我们**高度重合**且自称生产 | 产品线**互补**（开关柜/发电机/线路器材）|

**🆕 判据 A ·「三合一」**（三条同时出现 ⇒ 排除，成本最低，优先用）：
1. **产品跨度极大、跨越不相干行业**（如变压器 + HDPE 管材）
2. **自称 distributor / solution provider，却宣称「生产能力」**（产能是上游的）
3. **无自有工厂地址**（只有商务办公地）

**🆕 判据 B · 政府登记三件套**（有疑问时用来定案，**优先于官网措辞**）：
查 `https://cage.report/CAGE/<CAGE号>`（CAGE 号可从 SAM.gov 或 Google 搜 `"<公司名>" CAGE` 得到）：
- CAGE **`entity type`** = `A — U.S. or Canadian manufacturer` ⇒ 🚨
- 官方 NAICS 含 **335311 / 335313** ⇒ 🚨
- SAM business type 含 **`MF`**（Manufacturer）⇒ 🚨

> 📌 **边界**：CAGE `entity type = F — Vendor or distributor` 时，
> **即使官网出现 "remanufacturing" 字样也判保留**（Voyten、Dykman 即此例）。

**其他加分判据**：
- **UL 证书「Issued to」** 为**中国工厂** ⇒ 「中国源→北美」通道 ⇒ 排除

> ⚠️ 名字含 `Manufacturing` **不等于**制造商（可能只是「服务于制造业」）。
> ⚠️ 「当前是否有**在运**制造能力」才是判据，不看历史。
> ⚠️ **「重绕 / 翻新 / remanufactured」**：只做维修翻新**可留**；**在营绕线/总装产线 ⇒ 排除**。

**不过 → 不写交接单，改写成 `⛔排除{买家号}_{公司}_排除记录.md`**（含证据原文 + URL）。

### 第 1 步 · L-1 锁具名决策人

**优先级顺序**（按可靠性）：
1. **官网 Team / Leadership / Our Team 页** ← 🔴 第一方，最可靠
   （试 `/team/`、`/our-team/`、`/leadership/`、`/about-us/team/`、`/meet-our-team/`、`/company/`、`/about/`）
2. **官网 Contact 页 / 新闻稿署名 / PDF 手册署名**
3. **行业协会会员名录**（加拿大：CMEQ / ECAA / ECABC / NLCA / ECANS；美国：NECA 分会 / PCCA / NUCA / PEARL / NEMRA）
   → 检索式：`WebSearch "<公司名> <省/州> association member directory contact"`
4. **LinkedIn 个人页** —— ⚠️ **直接抓必然 999/451 失败，必须走 `WebSearch` 取摘要**
5. B2B 库（仅作旁证，**两库互证不算印证**）

**选谁**（每家只选 1 人）：
采购/供应商对接岗 > 国际销售/外贸岗 > 品类经理 > 老板/Owner > 普通业务顾问（兜底）

> 🔴 **一家公司只发 1 人。** 同域名多人 = 排重对象，不是机会。

**通关标准**：拿到 ≥1 份「**姓名 + 职能 + 在职证据 + 个人页 URL**」

### 第 2 步 · 找邮箱（先锁人，再找邮箱）

> 🔴 **batch7/8 已验证的方法结论：小微/家族企业的官网通常只挂 `info@`。
> 想要 A 档，必须离开官网。**

**A 档（具名邮箱）高产来源 —— 按 batch8 实测命中数排序，优先试**：
1. 🥇 **`cage.report/<CAGE号>` 的 "Published business email"**（batch8 命中 **6 家**）
   ⚠️ 三个坑：① 邮箱域可能 ≠ 官网域（拿到后必须 `dig MX` 复核）
   ② 记录可能是多年前的 NCAGE 存档 → 标「记录时效」
   ③ 登记 POC 可能是**荣休者** → 必须叠加官网高管页核当前在职性
2. 🥈 **CMEQ 持牌企业库（魁省）** `cmeq.org/trouver-un-entrepreneur/rbq-<licence号>/`
   —— 详情页**直接 mailto 具名负责人**（batch8 命中 2/2）。法语区老板邮箱公开度高，**但公开在协会库而非官网**
3. 🥉 **行业细分协会会员名录**（TECA / NECA 各分会 / PCCA / NUCA / PEARL / NEMRA）
   —— 会员名录常带**具名联系人 + mailto**
4. **官网 Careers / 招聘页** —— ⚠️ **必翻**！batch8 有一家的具名邮箱**只出现在 Careers 页**
5. **官网 footer 的 mailto** —— ⚠️ **WebFetch 抓不到（页脚被剥）→ 必须**
   `curl <url> | grep -oE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+'`
6. **省/州企业注册库**（州 SoS / 州 Corporation Commission / PUC / `opengovca.com` / ON 注册库）
7. **SMTP RCPT 探测**（见下）

**SMTP 探测规范**：
```
① 控制地址（该域已知真实的 info@）必须 250 —— 否则本轮整体作废
② 随机地址必须 550 —— 否则是 catch-all，探测无效
③ 候选地址 250 才可采信
```
> 🔴 **判据统一为「本域是否存在 550」，不看服务商**。
> batch8 实测：Google Workspace / M365 / Proofpoint **都可能可探测**
> （`{{COMPANY_DOMAIN}}`(Google)、`{{COMPANY_DOMAIN}}`(M365)、`{{COMPANY_DOMAIN}}`(Proofpoint) 均 随机550/真实250）。
> **必须实跑控制地址协议，不能按服务商预判。**
> ⭐ **进阶手法**：同域**第二个**具名邮箱也 250 ⇒ 把「单点命中」升级为「**规则级确认**」。

**❌ 明确无效（别浪费时间）**：B2B 库（ContactOut / Prospeo / LeadIQ / RocketReach）、
小微官网 Team 页、LinkedIn 个人页直取、archive.org

**🔴 邮箱域 ≠ 官网域（高频陷阱）**：
拿到邮箱后**先 `dig @8.8.8.8 <邮箱域> MX +short`**，确认该域真实存在且收信。
**绝不能按网站域名拼写收件地址。**

**邮箱分档**：
| 档 | 类型 | 可否主送 |
|---|---|---|
| **A** | 具名决策人邮箱（已验证，一手源）| ✅ 主送 |
| **B** | 角色邮箱（`info@` / `sales@`）| ⚠️ **仅点名转交** |
| **B−** | catch-all 域具名邮箱（无法验证）| ⚠️ 暂缓 |
| **C** | 免费邮箱 / 弱域 | 🔴 需电话确认 |

> 🔴 **H6**：仅拿到角色邮箱时，必须跑「升级三步」（挖职能邮箱 → 从回信反推命名规则 → 试推演），
> 失败则**显式写明「仅取得角色邮箱，未取得决策人直邮」并列为风险**。**禁止蒙混过关。**
> ⚠️ **推演出来的邮箱一律算 B 档，不得作主送。**

## 五、🔴 红线（违反即返工）

| # | 红线 |
|---|---|
| **H1** | 找不到必须写「未找到」，**禁止**用推测/常识填充 |
| **H2** | 🔴 **绝不编造邮箱/联系方式**（最高优先级）|
| **H3** | 邮箱须格式校验 + ≥1 来源交叉；单一来源须标注「未经第二方印证」 |
| **H4** | 必须标验证状态：`已验证 / 待验证 / 未找到` |
| **H5** | 交叉印证须含 ≥1 **一手源**（**两个 B2B 库互证不算**）|
| **H6** | 仅角色邮箱不得直接交付，须跑升级三步或显式标风险 |
| **H7** | 🔴 **产出必须落盘成 `.md` 文件** |

**其他必守**：
- ❌ 不写交期数字、不写价格词（首封红线，交接单里也别写进「开发信建议」）
- ❌ 不写 `CSA Certified` / `SASO` / `SONCAP` / `YAWEI`（可写 `built to CSA/IEEE/IEC standards`）
- ❌ 对**美国**客户**不谈干变**
- ❌ 供货记录 PDF **绝不外发**
- ⚠️ 遇到 Cloudflare / 验证码 → **先换 Googlebot UA 重试**，仍不行则停下报告，不硬闯

**环境坑（务必记住，全部是实测）**：
- 🔴 **本机 DNS 有 fake-ip 劫持**（返回 `198.18.0.x`）→ 验域名**必须** `dig @8.8.8.8` + `curl -sI` 交叉
- 🔴 **LinkedIn 个人页直接抓必失败** → 走 `WebSearch`
- 🔴 `web.archive.org` curl 超时 → 改用 WebFetch
- 🔴 **Cloudflare 403 会"骗人"** → 换 `curl -A "Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)"` 往往即 200
- 🔴 **Proofpoint 域可能给出误导性错误**：对 `info@` 回 `550 5.1.1 User unknown`（看似地址不存在），
  但紧接着对随机地址回 `421 too many errors` 并断连 ⇒ **实为网关拒探，不是地址不存在**
- 🔴 **`neo.space` MX 对任何 RCPT 统一回 `550 5.7.25 Cannot find your hostname`** → 整轮作废
- ⚠️ **MX 走 Mimecast（`*.mimecast.com`）→ 直接预判不可探测**（项目有 PBL 拦截史）
- ⚠️ **目录聚合站会产出稻草人数据**（555 电话 / 人名机械拼接）→ **整页作废**
- ⚠️ **GoDaddy 建站站点的 mailto 可能混入模板作者邮箱**（如字体作者）→ 必须剔除
- ⚠️ **类目名同形异义**：见到 "Transformers" 类目**必须点进去看 SKU**
  （batch8 实测有把 LED 低压驱动放在 `transformers` 类目下的）
