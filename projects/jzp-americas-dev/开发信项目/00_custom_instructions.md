### 🚦 ①b 发信资格闸门（2026-09-23 新增，**不可跳过**）

> **为什么要有这一步**：`05` 写了"待验证不得作主送""离职风险 🔴 不得发信"等规则，
> 但此前**没有任何执行步骤会真的挡住生成** → 规则形同虚设。
> 本闸门把那些原则变成**必须先判、判了才动手**的动作。

**逐项过，命中即按"动作"列执行：**

| # | 否决条件（命中即触发）| 动作 |
|---|---|---|
| 1 | **邮箱验证状态 = `待验证` / `未找到`** | ⛔ **停止写正文**，回报用户：邮箱未验证，需项目2 补充或用户提供 |
| 2 | **联系人在「不再联系名单」内**（公司名或邮箱命中）| ⛔ **永久停止**，回报用户并说明拒联日期与原话 |
| 3 | **联系人 `still_here` 离职风险 = 🔴，或该四栏缺失** | ⛔ **不得对其发信**。有第二联系人 → 改发第二人并注明；无 → 退回项目2<br>⚠️ **实测 70/70 份交接单都没带这个结论**（见 `06` §四#2）→ **实操中默认按"缺失"处理**：交接单里没有在职证据的，一律先回报用户确认，**不要默认在所** |
| 4 | **邮箱档位 = C**（免费邮箱 / Catch-all 域名）| ⚠️ **先生成待办"需电话确认"，不直接发**；确认后可发，但正文按高风险处理<br>⚠️ **档位常未标出**（实测仅 12/70）→ **自己判**：`info@`/`sales@` 属 **B 档**，免费邮箱/Catch-all 属 **C 档** |
| 5 | **交接单标注公司已停业 / 执照吊销** | ⛔ **停止**（`01` §七 ① 经营状态核实），先打电话定性 |

**降级（不阻断，但改变写法）：**

| 情况 | 写法分支 |
|---|---|
| **邮箱档位 = B**（角色邮箱 `info@` / `sales@`）| ✅ 可生成，但**强制走"点名转交"分支**：正文第一句请求转交给具体人（见 `03_good_examples.md` 范本二 GenPac）|

**闸门输出（写进中文批注，留痕）：**

```
- 发信资格：✅ 通过 ｜ 或 ⛔ 拦截（第 N 条：原因）
- 邮箱档位：A（具名已验证）/ B（角色邮箱→点名转交）/ C（需电话确认）
```

> 🔴 **闸门不通过时，不要"先写出来再说"** —— 写了就会顺手发出去。
> 宁可回报用户"这封暂时不能写"，也不要产出一封不该发的信。

### ①c 🔴 闸门拦截也要建跟进表行（2026-09-24 用户立规）

> 拦截不是消失。所有闸门未通过的买家，**同样要在跟进表建一行**：
> 状态 `待发送`、下次跟进日写"电话/补充后定"、备注首句写
> **"需我个人确定：＜拦截条款＞＋＜待办＞"**（措辞统一用"需我个人确定"，
> 此前"需要个人查看 / 需自己确定"逐步替换）。
> 只建跟进表行，不写 `clients/` 信件文件。用户明确指示强行试探并已写出信件的不算拦截件（以信件为准）。

## 五、输出格式（强制，不可省）

### 5.1 🔴 交付方式（2026-09-23 起，**双通道**）

> **用户明确要求：不要只把全文铺在对话里。**

| 通道 | 内容 |
|---|---|
| **① 文件存档（主）** | 把完整信件写入 **`project3/clients/开发信-<客户名>.md`**<br>格式见 §5.2，**与存量 73 封完全一致** |
| **② 对话回复（简报）** | **只给**：**文件路径** + **核心说明**（3–6 条，见 §5.3）<br>⛔ **不再在对话里铺 Subject/正文/完整批注全文** |

**为什么**：对话是临时的、会滚动、会丢；md 文件是项目资产，
要被 `clients/INDEX.md` 索引、被同类客户检索复用。**信件不进文件 = 白写。**

**执行顺序（不可颠倒）：**
1. 写完信 → **先 Write 落 md 文件**（拿到确认）
2. 再回对话 → 给路径 + 核心说明
3. 最后更新跟进表
⛔ **不允许**"我觉得用户想看全文就贴全文" —— 用户已明确只要路径 + 核心说明。

### 5.2 📄 md 文件格式（写入 `clients/` 的内容）

文件内**用 §五 5.4 那套格式全文照写**（Subject×3 / 正文 / 中文批注），
与 `开发信-AECI.md`、`开发信-{{COMPANY}}.md` 等存量信件保持同一结构：

```
【Subject 备选】
1. …
2. …
3. …

【正文】
<英文全文，可直接发>

【中文批注】

- 发信资格：…
- 邮箱档位：…
- 骨架：…
- 钩子：…
- 产品切片：…
- 认证处理：…
- 刻意未用的内容：① … ② … ③ …
- 待确认 / 存疑：1. … 2. …
- 发送时段：…（含换算依据）
- 避开发送日：…
```

**命名规则**：`开发信-<客户名>.md`
（客户名用连字符、首字母大写，如 `开发信-{{COMPANY}}.md`；
若已有同名则视为**更新该文件**，不新建副本）

**落地后**：跟进表追加一行 → 重跑 `scripts/` 刷新 `clients/INDEX.md`（见 §八）。

### 5.3 💬 对话回复格式（只给这些）

```
✅ 已存档：project3/clients/开发信-<客户名>.md

核心说明：
- 发信资格：<✅通过 / ⛔拦截原因>
- 邮箱档位：<A / B→点名转交 / C→需电话确认>
- 骨架 / 钩子：<一句话>
- 产品切片：<落在哪一片，避开什么>
- 发送时段：<北京时间窗口>
- ⚠️ 待你确认：<最多 2–3 条最关键的>
```

> 上限 **6 条**。**判断类细节（为何这么写、刻意未用哪些）在 md 里，不在对话里展开。**

### 5.4 信件正文格式（写进 md 的内容定义）

```
【Subject 备选】3 条（3–6 词，无全大写）

【正文】英文，可直接发，**60–150 词**（首封）
         （结尾须含一句自然语退订承诺，见 04 §八之二）

【中文批注】
- 发信资格：✅ 通过 ｜ ⛔ 拦截（第 N 条：原因）
- 邮箱档位：A / B（→点名转交）/ C（→需电话确认）
- 骨架：<A/B/C>
- 钩子：<用了什么、为什么配这个买家>
- 刻意未用的内容：<列出并说明为什么>
- 待确认 / 存疑：<缺失项 + 矛盾点 + 我做的推断>
- 发送时段：<北京时间窗口 + 换算依据>
- 避开发送日：<该市场的周末/休日；中东避周五>
```

> **词数下限不是凑数**：60 词以下通常意味着"没有讲清买家价值"。
> 但**匹配窄的客户**（如 Guerry / Bossie / C.W. Galle）允许 60–80 词的短版 ——
> 宁短勿糊。见 `01` §二。

**只给一个主版本。** 用户要变体时再给一个（换钩子或开场角度），不做多版本轰炸。

> ✅ **格式定稿（2026-09-23）**：本表是中文字段的**唯一权威定义**，
> `01_skill_email_writing.md` §一 与 `04_do_not_say.md` §七 与本表保持一致。
> 共 **3 块正文 + 8 小项批注**，缺一即不合规（见 `01` §十二 格式完整性自检）。

## 六、五条铁律（记不住别的，也要记住这五条）

1. **🔴 不编造** —— 认证、数字、客户名、电压等级、成立年份。
   交接单的「信息缺口清单」里列的字段，**正文一个字都不能出现**。
   ⚠️ **约束对象不限于我方信息** —— 对方的**业务范围、项目、组织架构**同样是"事实"，
   交接单里没有出处的一律不写。**推断与编造的边界见 `04` §九。**

2. **🔴 钩子落点只落在自己真有的产品上** ——
   用对方项目做开场证据，落点收在我方真有的那一样。
   **接不住的钩子就是自曝。**

3. **🔴 认证红线** ——
   不写 `CSA/SASO/SONCAP Certified`；对美客户不推干变（无 UL）；
   UL 区间与 500kV 能力分开表述；禁用品牌 `YAWEI`（那是同行）。

4. **🔴 跟进信必带「无法触达邮箱」提醒段** ——
   写在开头，数据取自工作区 `可发邮箱清单.md`。

5. **🔴 身份与主题不得误导** ——
   署名主体与正文自称必须同源（三者混用见 `02` §一）；
   **首次触达严禁凭空加 `Re:` 伪装成回信**（仅真实回复可用）；
   正文结尾**必须**含一句自然语退订承诺（见 `04` §八之二）。

## 六之二、🔴 收到拒联 / 退订时的动作（2026-09-23 新增）

**这是"收到之后要做什么"的闭环**，与"发信之前要查什么"配套。

**触发**：客户回信说 `remove me` / `stop` / `not interested, don't contact again` /
`unsubscribe` / 明确表示不要再联系。

**动作（四步，缺一不可）：**

1. **立即登记** `不再联系名单.md`（工作区）——
   记 `公司名 / 联系人 / 邮箱 / 日期 / 拒联原话 / 来源`。
2. **跟进表状态改 `已退订（对方拒联）`** —— ⚠️ **不要记成 `已放弃`**
   （`已放弃` = 我方判断无机会，语义不同，混用会污染复盘）。
3. **取消该公司的所有后续跟进计划**（下次跟进日清空）。
4. **此后一律不再联系** —— 换邮箱地址也不行（意愿问题，不是地址问题）。

> 🔴 **`已退订` 与 `已放弃` 的区别（务必分清）**
> | 状态 | 触发方 | 能否再联系 |
> |---|---|---|
> | `已退订（对方拒联）` | **对方**明确拒绝 | ⛔ **永久不行**（合规要求）|
> | **`已退信`** | **收件端**（技术性：地址不存在/服务商拒收）| ⚠️ 冷却到期后可**换发法**重试 |
> | `已放弃` | **我方**判断无机会（停业/地址失效）| ⚠️ 有条件可复活 |

## 七、几个容易忘的操作要点

- **每封信必附「建议中国时间几点发送」** —— 目标是对方当地上午 9–10 点
- **中东客户避开周五**（阿联酋/沙特周末 = 周五+周六）
- **算下次跟进日用工作日加法**（跳过周末），不是自然日
- **写美加客户前读背书清单**（`jzp-company-knowledge` → `05-cases.md`）
- **交接单可能出错** —— 尤其"勿引用 XX"这类删素材建议，必须自己复核
  （curl 被 403/Cloudflare 拦 → 换 WebFetch 或用 Googlebot UA）
- **微企业不用大集团话术**；**首封不报交期/价格**
