## 提示词正文（从这里开始整体复制）

```
你在为一位 AI 外贸顾问整理知识库。source 是毅冰《十天搞定外贸函电》（2012.10，正文 280 页）。
请把全书提取成一份 markdown 范文库 + 方法论稿，供 AI 在真实外贸业务中直接调用。

【最高原则：保真优先于压缩】
这本书的价值就在例句和范文本身，不是它的目录。
- 禁止摘要、改写、意译、合并同类项、合并不同情境。
- 英文原文逐字保留，包括书中的拼写错误、大小写、标点习惯，一律照抄，不得"顺手改对"。
  若发现明显笔误，在句末用 `〔原文如此〕` 标注，不要改动原文。
- 中文讲解可压缩，但判断标准、数字、条件、时间期限一个都不能丢。
- 宁可长，不可省。篇幅不是问题，漏内容才是问题。

【删除规则】
出现以下内容的页面整页跳过，不占篇幅：
- 卖家引流页（含 "hxg3366b"、微信二维码、"本人外贸14年，社媒运营7年"字样的页）
- 课程推广页、扫码页、"更多外贸内容请加微信"类页面
- 纯粹的寒暄段落、与本章主题无关的闲聊
- 与其他单元重复的案例叙述（保留首次出现的完整版，后续只写"见第X天"）

【参数化规则】
只替换具体专名，不动句式结构：
  人名→[Name]  公司→[Company]  产品→[Product]  国家→[Country]  金额→[Amount]  日期→[Date]
书名号《》保留（这是中文讲解部分）。英文正文里的引号、破折号等标点保持原样。

【输出结构】

开头加 frontmatter：
---
title: 十天搞定外贸函电（全书范文库）
source: 毅冰·十天搞定外贸函电（2012.10，280页）
type: methodology
summary: 十天十单元，覆盖外贸函电全流程情境、判断标准与可复用句式库
tags: email, business-correspondence, negotiation, order-followup, claim
---

正文按「天」分一级章节，按书中二级小节分二级章节：

## 第X天 中文标题 / English Title

### X.N 小节中文标题 / English Title

- **适用情境**：一句话，什么情况下用这个写法
- **要点**：作者给的方法、判断标准、注意事项（有几条写几条，用 - 列表）
- **风险**：如果作者点了坑，写这里；没有就省略这一行

#### 范例
> 英文原文，逐字，整段放引用块
>
> 如有多个范例，用 --- 分隔，每个范例前加一行小字说明它对应什么场景

（若书中有中文对照译文，另起一行放在该范例下方，格式：`中译：……`）

#### 句式
- `[可复用的英文句式]` — 适用：[什么场景]
- 该小节没有独立句式时，省略此块，不要硬凑

【分批协议（必须遵守，否则会被截断）】
全书 280 页，一次性输出必然截断。请按以下节奏：

- 本次只输出 **第一天** 的全部内容，输出完在最后单独一行写：
  `【已输出 第1天 / 共10天，待续】`
- 我回复 `继续`，你再输出下一天，依此类推。
- 我回复 `跳到第X天继续`，从第 X 天开始。
- 每批必须输出完整，宁可分两天也不要在一批里砍内容。

【自检（每批输出前默检，不通过就不要输出）】
- [ ] 该天所有二级小节都已覆盖，编号连续无跳号
- [ ] 每个小节的英文范例都是逐字原文，没有被我改写或"润色"
- [ ] 判断标准里的数字（天数、比例、金额区间、AQL 等级等）全部保留
- [ ] 专名已参数化，句式结构未动
- [ ] 引流页/推广页已跳过
- [ ] 没有出现"综上所述""总而言之"这类我自己的总结

【格式纪律】
- 只输出 markdown 正文，禁止开场白（如"好的，我来为您整理"）、禁止结尾总结
- 不要输出你的思考过程
- 不要用 emoji
```

## 收尾核验（全部批次出完后发这一段）

```
请做一次完整性自查，只输出结果，不要重新输出正文。

1. 列出本书实际的天数、每天的小节数量，以及你已输出的天数与总小节数。
2. 对照原书，逐天核对：有没有哪个小节被漏掉？有则列出「第X天 X.N 标题」。
3. 有没有哪个小节的英文范例被我改写、精简或省略？有则列出位置。
4. 有没有哪条判断标准里的数字被丢了？有则列出。
5. 最后给一个总字数与总范例数。
```
