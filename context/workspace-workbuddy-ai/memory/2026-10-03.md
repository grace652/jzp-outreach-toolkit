## 18:50 用户追问：DKIM / DMARC 具体怎么获取（用腾讯企业微信）

### 实测复查（2026-10-03，`dig @8.8.8.8`，**DNS 未被 TUN 劫持，结果可信**）
| 记录 | 结果 |
|---|---|
| MX | `mxbiz1.qq.com` / `mxbiz2.qq.com` ✅ |
| SPF | `v=spf1 include:spf.mail.qq.com ~all` ✅ 已有 |
| **DKIM** | ❌ `dkim`/`default`/`tencent`/`mail`/`qq` 五个选择器**全空** |
| **DMARC** | ❌ `_dmarc` 无返回 |

⇒ 确认只缺 DKIM + DMARC，**SPF 不用动**。

### 🔑 核心认知：两者的获取方式根本不同
- **DKIM = 后台「生成」** —— 私钥在邮局，你只能复制公钥，**不能自己造**
- **DMARC = 自己「写」** —— **没有任何生成入口**，按标准格式手写 TXT

### 官方路径（腾讯企业微信帮助中心 19647 / 21540）
**DKIM**：
1. 【协作 → 邮件 → 邮箱域名】确认状态「使用中」
2. 【协作 → 邮件 → **安全管理** → **DKIM验证** → 配置】← 在「安全管理」下，不是「域名管理」
3. 原样复制：主机记录 + 记录类型 + 记录值
4. DNSPod 加 TXT
5. **回后台点「已完成配置，立即验证」** ← 最容易漏，不点永远是「验证中」

**DMARC**：DNSPod 加 TXT，主机记录 `_dmarc`，
值 `v=DMARC1; p=none; rua=mailto:{{SENDER_EMAIL}}; fo=1`

### ⚠️ 与官方文档的重要分歧（我给的更保守）
腾讯官方示例是 `p=reject`，但**我建议先用 `p=none`**：
现在 DKIM 还是空的，若还有第三方（阿里国际站/CRM/表单）在用该域发信，
`p=reject` 会**立刻拒收这些正常业务邮件**。正确顺序：`none` →（2-4 周）→ `quarantine` →（2 周）→ `reject`。

### 官方列出的五个坑
记录值带空格（首要原因）｜大小写被改｜主机记录写了全域名｜DMARC 直接上 reject｜加完不点验证
