# 作战手册骨架与 CSS 要点

## 一、章节骨架

```
封面
  kicker（公司名 · Market Development Playbook）
  h1（区域 + 客户开发作战手册）
  sub（覆盖国家 + 执行窗口）
  meta（主体 / 产品 / 资质 / 编制日期）

「本手册的三条前提」callout
  1. 结论先行，来源可查
  2. 区分事实与推断
  3. 不编造联系方式

目录（两栏，用 columns:2）

0  执行摘要：三条结论
    每条一个 .verdict 框：结论 + 依据 + 「→ 所以呢」
    0.1 必须先修的问题（流水线补丁，附实测数据）
    0.2 一句话战略

1  市场态势
    1.1 主市场（供需 / 交期 / 价格 / 存量老化）
    1.2 次市场
    1.3 新区域（先定频率/标准体系，再定国别）

2  政策与关税地图        ← 最重要的一章
    2.1 关税重构时间线（表格：时间 / 事件 / 影响）
    2.2 按产品线的税负表
    2.3 政策禁入区（比关税更硬）
    2.4 次市场关税
    2.5 能效法规（硬节点）

3  认证准入矩阵
    表格：市场 / 频率 / 标准体系 / 强制认证 / 我方现状 / 缺口与动作

4  买家地图与目标清单
    4.1 买家分层（类型 / 规模 / 门槛 / 决策链 / 打法）
    4.2 新区域目标清单（分梯队）
    4.3 现有线索池的二次利用

5  线索获取渠道
    5.1 海关与贸易数据平台（对比表）
    5.2 免费官方数据源
    5.3 买家名录与行业协会
    5.4 展会参展商名录（最被低估的免费渠道）
    5.5 招标与采购公告
    5.6 渠道投入建议（排序 + 成本 + 理由）

6  竞争格局与我方定位
    6.1 中国同行（找标杆案例）
    6.2 主市场本土制造商
    6.3 新区域本土制造商
    6.4 我方的 N 个优势与 N 个短板（左右对照表）
    6.5 定位陈述（可直接用于开发信首段）

7  开发执行系统
    7.1 语言线 × 打法（主诉求 / 副诉求 / 必须避免）
    7.2 触达节奏（Mail Group 分工表）
    7.3 报价策略
    7.4 案例引用授权
    7.5 售后与备件（复购的真正决定因素）

8  90 天行动计划
    第 1–2 周 / 第 3–4 周 / 第 5–8 周 / 第 9–12 周
    每项：序号 / 动作 / 验收标准
    关键里程碑 .callout

A  来源清单（按主题分组，纯 URL 列表）
B  待核实清单（表格：# / 事项 / 影响 / 核实方式 / 优先级）

footnote（编制日期 + 免责说明）
```

## 二、CSS 要点

```css
@page { size: A4; margin: 18mm 16mm 20mm 16mm; }   /* 必须写，否则 Chrome 出 Letter */

:root{
  --ink:#1a1f2b; --ink-2:#3d4657; --ink-3:#6b7488;
  --line:#dfe3ea; --line-2:#eef1f6; --bg-soft:#f7f8fa;
  --navy:#1c3b6e; --navy-soft:#eaf0f9;
  --red:#a8232b;  --red-soft:#fdeeee;
  --amber:#8a5a00;--amber-soft:#fdf4e3;
  --green:#1f6b3a;--green-soft:#e9f5ed;
}

body{
  font-family:"PingFang SC","Heiti SC","Microsoft YaHei",sans-serif;
  font-size:10.5pt; line-height:1.75; color:var(--ink);
}
.page{max-width:186mm;margin:0 auto;}   /* 配合 A4 左右各 16mm */

h2{ font-size:15pt; color:var(--navy); border-bottom:1.5px solid var(--navy);
    page-break-after:avoid; }            /* 标题不孤行 */
table{ page-break-inside:avoid; }        /* 表格不跨页 */
.pb{ page-break-before:always; }         /* 章节强制分页 */
```

**打印相关必做**：
- `page-break-after:avoid` 加在所有标题上
- `page-break-inside:avoid` 加在表格、callout、verdict 上
- 每个主要章节加 `class="pb"` 强制分页

**组件**：
- `.callout`（四色：默认蓝 / `.warn` 红 / `.ok` 绿 / `.amber` 黄）—— 用于补充说明与警示
- `.verdict`（白底深蓝边框）—— 用于核心结论条
- `.tag`（`.go` / `.no` / `.mid` / `.info`）—— 表格内的状态标记
- `.src`（小字灰色，`word-break:break-all`）—— 来源 URL
- `.rank`（圆形序号）—— 排序类内容

## 三、写作纪律

1. **每个结论都要回答「所以呢」。** 不要只陈述「交期 128 周」，要写「所以客户最在意的排序是交期 > 认证 > 价格」。

2. **主动写出对自己不利的结论。** 例：「GSU 与变电站变压器增速虽高，却恰好是政策禁入区。增速最高的市场对你关门，增速最低的市场向你敞开。」——这种错位判断比罗列机会有价值得多。

3. **区分「已证实」与「未证实」。** 关税数字必须标注「估算值，须报关行核定」。认证口径冲突时，明写「官网与行业资料矛盾，必须书面确认」。

4. **不要用「大概」「可能」掩盖不确定。** 要么给出具体数字与来源，要么写「未查到公开信息」。

5. **附录 B 待核实清单是硬要求。** 把不确定项集中列出，标优先级，给出核实方式。**5 项以内标「最高」**——全是最高就等于没有优先级。

## 四、转换命令

```bash
# HTML → PDF
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --no-sandbox --disable-gpu --disable-dev-shm-usage \
  --no-pdf-header-footer --virtual-time-budget=8000 \
  --print-to-pdf="out.pdf" "file:///abs/path/in.html"
ls -la out.pdf      # 必须确认文件真的存在！退出码不可信

# HTML → DOCX
/Users/eric/.venv-html-to-docx/bin/python - <<'PY'
from html4docx import HtmlToDocx
import pathlib
h = HtmlToDocx()
doc = h.parse_html_string(pathlib.Path("in.html").read_text(encoding="utf-8"))
doc.save("out.docx")
PY
```

**交付时明确告知用户**：PDF 是保真版（阅读/打印），DOCX 是编辑版（排版会简化），两者内容一致但视觉不同。
