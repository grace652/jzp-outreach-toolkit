## 一、定位与边界

### 这个文件解决什么

## 二、决策流程（拿到客户背景后）

```
① 客户近 30 天内有没有「自身事件」？
   （新厂 / 扩张 / 中标 / 关键招聘 / 新品发布 / 融资）
   ├─ 有 → 用【客户事件】开场（外部成熟方法，见 §五 B 型）
   │        ★ 但必须遵守毅冰纪律：不赞美、不点评、只陈述事实
   │
   └─ 无 → ② 有没有匹配的行业信息？
            （A/B 级、含 followup、lint 通过、地域/买家/产品线匹配）
            ├─ 有 → 用【行业信息】开场（毅冰 §1.5 法，见 §五 A 型）
            └─ 无 → ③ 走 §八 回退
```

### 🔴 三条铁律

1. **一次只用一个触发点。** 要么客户事件，要么行业信息，**不并列、不叠加**。
   （外部实践共识：叠加两个信号会让邮件显得用力过猛、模板感强）
2. **客户事件当「钩」，行业信息当「值」。** 前者证明「我了解你」，后者证明「我能帮你」。
3. **没有第三条信息就不写。** 宁可退回毅冰现有 5 个角度，**绝不硬凑**。

## 三、信息筛选标准

### ✅ 可以用的

| 条件 | 说明 |
|---|---|
| 可追溯 | 有 `source_url` + `published_at` |
| 可信度 A 或 B | A = 监管/官方（如 Federal Register、DOE）；B = 行业媒体 |
| `quote_ready_en` 非空 | 已预审的英文句，可直接改写成开场 |
| `usable_in` 含 `followup` | 标记为可用于跟进信 |
| 时效新 | 一般 ≤30–45 天；**标准 / 法规类可放宽**（生效日仍在未来即可）|
| 与客户业务相关 | 地域、买家类型、产品线至少一项对得上 |

### ⛔ 不能用的

| 禁止 | 原因 |
|---|---|
| C 级（聚合源）未核实 | Google News 链接需人工打开核实原文，**引用前必须标注真实媒体名** |
| `category == competitor` | **仅内部参考**。`04-不要说什么` 明令：不得与竞品对比、不得点名对方独家品牌 |
| `do_not_say_flags` 非空 | 脚本已标出红线（含交期/价格语义、spam 词等）|
| 含**交期或价格数字** | 毅冰红线：**首封不报交期/价格**；跟进信引用也必须有出处 |
| 命中 spam 词 | `free` / `discount` / `best price` / `guarantee` / `100%` / `!!!` |
| `CSA Certified` / `SASO` / `SONCAP` / `YAWEI` | 我方无这些证书；`YAWEI` 是同行品牌 |
| 任何需要编造的内容 | 毅冰铁律：宁缺毋滥 |

## 四、取数步骤

### 命令

```bash
PY=python3
cd "<项目根>/行业数据"

# 按客户画像筛（推荐）
$PY 抓取/抓取行业数据.py --pick --geo US --buyer EPC --product distribution --limit 3

# 需要聚合源时（须人工核实）
$PY 抓取/抓取行业数据.py --pick --include-c --limit 5

# 看全库（人读，不用于取数）
$PY 抓取/抓取行业数据.py --render-only && open 出口/行业数据索引.md
```

### 参数含义

| 参数 | 取值 | 对应客户画像 |
|---|---|---|
| `--geo` | `US` / `CA` | 客户所在国 |
| `--buyer` | `utility` / `EPC` / `distributor` / `datacenter` | 客户类型 |
| `--product` | `distribution` / `power` | 谈的产品线 |

### 输出字段怎么读

```
## 1. <标题>
- 来源：<媒体名>（A/B/C）<url>     ← A/B 可直接用；C 须人工核实
- 发布：2026-10-02                  ← 判断时效
- 可用英文句：<预审句>               ← 改写成开场句的原料
```

### 挑选方法

1. **先按 `geo` 取**，对不上再退 `buyer`，再退 `product` —— **至少一项对得上**
2. **只取 1 条**。多条会让你想叠加，违反铁律
3. 取到的条目**必须能在信里说出处**（内部批注里写清来源与日期）

## 五、融入写法

### 通用结构（4 拍）

```
信息句（1 句，具体、带时间/来源）
   ↓
桥到产品价值（1 句）
   ↓
一个钩（1 个，不要多）
   ↓
低门槛 CTA（一句能答"好/不好"的问句）
```

**开场句规格**：≤20 词、具体、不赞美、不引私人生活、**不出现 `Y`**（毅冰：像群发模板）。

### A 型 · 行业信息开场（毅冰 §1.5 法）

**场景**：美国 EPC 客户，跟进信第 6 封，想带一条行业新信息。

**信息**：DOE 配电变压器能效标准提案（Federal Register，A 级）

**中文思路**：2026 年 DOE 出了配电变压器能效新规 → 很多电力公司正在重核规格 → 我们的产品已按新标准设计 → 要不要规格书？

**英文**：
```
A new DOE efficiency rule for distribution transformers came out this June.
Several utilities are re-checking their specs because of it.
Our [Product] is already built to it — want the spec sheet?
```

**写法拆解**：
- 第 1 句：**具体**（谁发的、什么时候），不评价、不夸张
- 第 2 句：说明**行业影响**（为什么这条信息对客户有用）—— 这是毅冰说的「让客户觉得能在你身上学到东西」
- 第 3 句：**桥到自己的产品**，给一个能一句话回答的 CTA

### B 型 · 客户事件开场（外部成熟方法）

**场景**：客户刚中了标 / 开了新厂 / 在招电气工程师。

**英文**：
```
Saw [Company] won the [Project] contract last month — congrats.
If the transformer package is still open, we could quote against the spec.
```

**⚠️ 与毅冰纪律的冲突处理**：
外部方法常教「先恭维（congrats）」，但毅冰反对谄媚与无意义客套。
**折中做法**：`congrats` 只用**一次、一个词**，紧跟**实质性内容**，不展开赞美。若客户是微企业或对方文化不喜客套，**直接去掉 congrats**，从事实切入。

### C 型 · 事件营销（毅冰 §1.10 原法）

毅冰原文范例：
> "First of all, Congratulations on your country win the champion of World Cup 2014, it's really fantastic! / As know from your website, you are a distributor of some famous brand silicone like Wacker, smooth-on, ACC, right?"

**结构**：大事件祝贺（1 句）→ **"As know from your website, you are…"**（把话题拉回客户业务）→ 市场分析（虚实结合）。

**注意**：毅冰批注「市场分析加上城市虚实结合，吊一下客户胃口」—— 城市名要有，但不要堆砌。

### D 型 · 同类产品讨论（《十天函电》法）

> "As I know, lots of US retailers begin to use Li-ion power tools."

**结构**：`As I know, <市场趋势> + <客户同类产品>`。一句就够，**不展开成行业科普**。

## 六、与 5 个切入角度的关系

本文件有**双重身份**，按此优先级使用：

| 身份 | 用法 | 何时用 |
|---|---|---|
| **① 贯穿层（优先）** | 为现有角度 2（热卖产品）/ 3（品质）/ 4（情怀）**供给「新信息点」** | 有匹配行业信息时 |
| **② 独立第 6 角度** | 整封信以行业信息为主轴（对应 `04` §四 新增的第 6 行）| 无其它钩、且信息足够强时 |

**判断**：先试 ① —— 把行业信息**嵌进**已有角度里，信更自然；只有当信息本身足够有力、足以撑起整封时，才用 ②。

## 七、避坑清单

### 毅冰禁区（必须遵守）

- **一对一，不群发** ——「邮件必须一对一，不能复制粘贴……要针对每个客户'量身定做'」
- **不出现 `Y`** ——「最好不要出现'Y'这个符号，容易让客户觉得这是一封群发的模板邮件」
- **不写 "Any news?" 式跟进** —— 毅冰批评这类「缺乏自己的东西，没有亮点」
- **不无休止 push** —— 《成交技巧2》案例 1-4：连续催促的客户会把人拉黑
- **主题必须明确** ——「没有明确的主题，会让客户根本没兴趣去打开陌生人的邮件」
- **跟进信 ≤120 词**，主题 3–6 词，无全大写、无感叹号堆叠

### 外部实践总结的错误

| 错误 | 为什么不行 |
|---|---|
| **赞美式开场** | 「I loved your recent post…」已被买家一眼识破，回复率崩塌 |
| **引用私人生活信号** | 提到对方的假期照片等 → 从「相关」越界到「令人不适」 |
| **叠加两个信号** | 一次只用一个触发点 |
| **信息与客户无关** | 硬贴行业新闻，读者立刻感到「这是群发」 |
| **写成行业科普长文** | 毅冰：开发信精髓是「简洁、简洁、再简洁」 |
| **空白 / 兜底字段残留** | 出现「As I know, 」后面空着 —— **比不写更糟** |

## 八、回退逻辑

取不到信息时，**按顺序降级，绝不编造**：

| 级别 | 做法 |
|---|---|
| **L1** | 用客户自身事件（近 30 天的扩张 / 中标 / 招聘）|
| **L2** | 用行业信息模块的数据（`--pick` 取到）|
| **L3** | 用**行业通用开场**（不依赖数据，如「电网投资周期」「数据中心用电增长」这类公认趋势）—— **不得带具体数字** |
| **L4** | 退回毅冰现有 5 个切入角度（样品 / 热卖 / 品质 / 情怀 /「无赖」）|

**数据模块不可用时的处理**（对齐 `SKILL.md` §六）：
在回复中写明「本次未取到行业信息，基于骨架完成」，**不报错、不中断、不编造**。
