# 外贸 B2B 客户开发系统 · 可复用框架

一套**跑通过真实业务的外贸客户开发流水线**：找客户 → 挖决策人 → 写信 → 发送排程 → 回复识别。
本仓库是**脱敏后的功能框架**：所有客户数据已清除，所有身份信息已占位符化，
你照着填自己的信息就能用。

> 拿到后先读 **`脱敏说明与填写指引.md`**，把 `{{...}}` 占位符替换掉再开始。

---

## ⚠️ 三条必读

1. **所有 `{{...}}` 占位符必须先替换** —— 脚本、信件模板、凭据里都有。
   `开发信-样例公司.md` 等样例文件**仅供照抄，勿直接发送**。
2. **客户数据已全部清除** —— 交接单、客户信、跟进表、线索名单、发信队列、退信记录都不在仓库里。
   你需要自己从零建档，或用 `线索资产/目标客户清单-空模板.csv` 填。
3. **不要注册定时任务跑自动发送** —— 手动排程、逐批核对。自动发送一旦配错会重复发信、且不可撤回。

## 怎么用

**所有脚本通过 `run.sh` 调用**（它会自动切到项目目录）：

```bash
./run.sh 发送层自检.py                 # 改动代码后必跑：34 项
./run.sh 扫描回复.py --days 14         # 扫描客户回复（只读，安全）
./run.sh 扫描退信.py                   # 扫描退信
./run.sh scripts/检查重复正文.py --check <队列.json>
./run.sh 邮箱客户端.py setup           # 配置邮箱凭据
```

依赖：核心链路**纯标准库**；跟进表相关需要 `pip3 install openpyxl`。

## 几条铁律（从真实事故里攒的）

1. **只发 A 档邮箱** —— 具名 + 已验证才发。角色邮箱（`info@`/`sales@`）退信率 14.3%，
   具名邮箱 4.2%，差 3.4 倍，而且退信会拖累整个发信域的送达率。
2. **退信闸门** —— 同域累计 ≥2 个地址退信 ⇒ 整域封锁（对方是按域封的，换人名没用）。
   跟进信要求**零退信**：冷却到期也仍拦截。
3. **同一封信不得对同一人发第二次** —— 排程前必跑 `检查重复正文.py --check`。
   `开发信-跟进-XXX.md` 是「第 N 轮的信」，不是可复用模板；第 2 轮必须另写。
4. **时区必须手工指定** —— 不要自动推断，实测会判错（信会在错误的时间送达，不报错但打开率变低）。
   交付前验算每封的当地送达时间应为 09:xx。
5. **收件地址必查拼写** —— `gmai.com` 这类近似域名**有有效 MX**，会误投给陌生人，比退信危险得多。
6. **规则要落到代码** —— 这几条铁律当初只写在文档里，结果全踩了一遍。

## 公司信息（1.4G）怎么用

`assets/公司信息/` 下有证书、规格书、产品目录、图纸、培训资料。
写邮件要发资料给客户时，从这里取。**注意**：引用客户名前要取得书面授权。

---

## 不包含什么

- **客户数据**（交接单 / 客户信 / 跟进表 / 线索名单 / 发信队列 / 退信记录）—— 已全部清除
- **邮箱凭据** —— 仓库里只有模板，真实密码在你自己机器的 `~/.config/jiezou-mail/config.json`
- **海关抓取数据**（`jiezou-kb/data`）—— 付费平台导出，有授权限制，可重新生成
